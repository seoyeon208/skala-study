# 15개 복습 노트 시각화 개선 설계

## 목표

- `lectures/00`부터 `lectures/14`까지 15개 복습 노트에서 글만으로 이해하기 어려운 관계를 시각화한다.
- 과정, 비교, 계층, 시간 변화, 선택 기준을 내용에 알맞은 도식으로 표현한다.
- 기존 설명과 퀴즈를 유지하면서 복습 속도와 개념 연결성을 높인다.
- 홈 카드와 머신러닝 페이지에서 `Day 1–3` 또는 `Day 1-3` 표현을 모두 제거한다.

## 선택한 방향

관계 맞춤형 방식을 사용한다. 모든 내용을 같은 카드나 흐름도로 만들지 않고, 관계의 종류에 따라 기존 컴포넌트를 선택한다.

- 순서·과정: `.flow`, `.flow-step`, `.flow-arrow`
- 층위·구성: `.stackbox`
- 개념 비교: `.compare-grid`, 표
- 핵심 지도: `.overview-grid`
- 시간·상태 변화: 기존 세로 흐름 패턴 또는 최소한의 공통 타임라인 스타일

흐름도 일변도 방식은 비교·계층 관계가 왜곡되어 제외한다. 모든 내용을 카드로 만드는 방식은 긴 문서에서 정보 우선순위가 약해져 제외한다.

## 페이지별 범위

1. Python 기초: 실행 순서, 자료구조 선택, 함수·객체 관계
2. Python 데이터 분석: NumPy/Pandas 처리 흐름, 인덱싱·결측 처리, 분석 파이프라인
3. Smart Data: 데이터 구조, SQL 실행 순서, 트랜잭션, ERD 관계
4. 기초 통계: 분포, 기술통계와 추론통계, 가설검정, 신뢰구간
5. Prompt Engineering: Prompt 구성 요소, Context 계층, Agent 실행 흐름
6. LLM·Transformer: Token부터 출력까지, Attention, 학습과 추론
7. Spring Boot REST API: 요청 처리 계층, JPA 생명주기, 예외 처리
8. Agile·MSA: Sprint 반복, Monolith와 MSA, CI/CD 흐름
9. sLLM Fine-tuning: 데이터 준비, LoRA 학습, 평가·서빙
10. Feature Engineering: 생성·변환·선택, 분할 경계, Leakage
11. Vue.js: 반응성, 컴포넌트 통신, 생명주기, 빌드·배포
12. Docker: 기존 도식 유지, 이미지·컨테이너·볼륨·네트워크의 빈 관계 보강
13. Kubernetes: Control Plane과 Worker, Deployment·Service·Ingress, 배포 흐름 보강
14. 머신러닝·딥러닝: 문제별 모델 지도, Bias–Variance, Ensemble, 신경망 학습 루프
15. 모델 개발·최적화: 분할·누수, 지표 선택, SHAP, Drift 대응

페이지당 2~4개의 핵심 도식을 기본으로 하되, 이미 충분한 도식이 있는 Docker·Kubernetes·Vue는 중복을 추가하지 않는다.

## 구현 원칙

- 외부 이미지, 차트 라이브러리, 새 JavaScript 의존성을 추가하지 않는다.
- 기존 HTML/CSS 컴포넌트를 우선 재사용하고, 표현할 수 없는 관계에만 공통 CSS를 최소 추가한다.
- 도식은 장식이 아니라 주변 설명을 읽지 않아도 핵심 관계를 파악할 수 있어야 한다.
- 도식 뒤의 기존 상세 설명은 삭제하지 않는다.
- 다크 모드 색상 변수를 그대로 사용하고 모바일에서는 가로 흐름을 세로로 전환한다.
- 색만으로 의미를 전달하지 않고 텍스트 라벨과 방향 기호를 함께 제공한다.

## 검증

- 15개 페이지가 공통 CSS를 불러오는지 검사한다.
- 각 페이지에 최소 2개의 시각화 블록이 있는지 검사하되 기존 도식도 인정한다.
- 모든 내부 링크와 ID가 유효한지 검사한다.
- `Day 1–3`, `Day 1-3` 문구가 홈과 머신러닝 페이지에 남지 않았는지 검사한다.
- JavaScript 문법, CSS 괄호, 기존 Docker·Kubernetes·머신러닝·모델 개발 테스트를 함께 실행한다.

## 완료 기준

- 15개 페이지의 주요 과정·비교·계층·시간 관계가 시각화되어 있다.
- 데스크톱과 모바일에서 도식이 겹치거나 잘리지 않는다.
- 기존 학습 내용과 퀴즈가 보존된다.
- 변경사항은 사용자가 확인하기 전까지 원격 저장소에 푸시하지 않는다.
