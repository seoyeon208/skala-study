1.JavaScript가 움직이는 방식

인터프리터 · 동적 타이핑 · 싱글 스레드 · 값과 참조

💡
JavaScript는 한 명의 요리사가 한 줄씩 주문을 처리하는 것과 같습니다. 오래 걸리는 요청은 브라우저에게 맡기고, 완료 알림을 받은 뒤 콜백을 실행합니다. 싱글 스레드와 비동기는 모순이 아닙니다.
  • 동적 타이핑: 값이 들어오는 순간 타입이 정해집니다.
  • 싱글 스레드: JavaScript 실행 스택은 한 번에 한 작업만 처리합니다.
  • 원시값은 값 자체를, 객체·배열·함수는 참조를 다룹니다.
  • 비교는 형 변환이 없는 ===를 기본으로 사용합니다.
const가 객체 내부 변경을 허용하는 이유
const user = { name: '서연', level: 1 }
user.level = 2        // 가능: 같은 객체 내부 값 변경
// user = { level: 3 } // 불가: 다른 객체로 참조 재할당
Q. const는 상수인데 왜 push()가 되나요?
A. const가 고정하는 것은 객체의 내용이 아니라 변수가 가리키는 참조입니다. 배열을 통째로 재할당할 수는 없지만 같은 배열에 요소를 넣는 것은 가능합니다.
강의에서는 이해를 위해 JavaScript를 “인터프리터 언어”로 설명했지만, 현대 브라우저 엔진은 성능을 위해 JIT 컴파일도 사용합니다. 복습할 때는 실행 전에 Java처럼 별도 빌드 산출물을 만들지 않아도 브라우저가 실행하며, 많은 오류가 런타임에 드러날 수 있다는 의미로 이해하면 충분합니다.

3.Promise와 async/await

비동기 요청의 완료·실패·마무리

💡
Promise는 “결과가 나중에 도착할 영수증”, await는 그 영수증의 결과를 해당 async 함수 안에서 기다리는 문법입니다. 브라우저 전체가 멈추는 것은 아닙니다.
실무에서 읽기 쉬운 비동기 패턴
const loadWeather = async () => {
  isLoading.value = true
  try {
    const response = await axios.get('/weather')
    weather.value = response.data
  } catch (error) {
    message.value = '날씨를 불러오지 못했습니다.'
  } finally {
    isLoading.value = false
  }
}
  • async 함수는 항상 Promise를 반환합니다.
  • await는 기본적으로 async 함수 안에서 사용합니다.
  • try/catch/finally로 성공·실패·로딩 종료를 분리합니다.
  • 서로 독립적인 여러 요청을 순서대로 기다리지 말고 필요하면 Promise.all()로 병렬 처리합니다.

4.Vue·SPA·SFC의 큰 그림

MVVM · Virtual DOM · Single Page Application · Vite

💡
상태가 원인이고 DOM은 결과입니다. 직접 DOM을 고치기보다 상태를 바꾸면 Vue가 필요한 화면만 갱신합니다.
  • SPA: 최초에 하나의 HTML을 받고, 이후 화면 전환은 컴포넌트를 교체합니다.
  • MVVM: Model(데이터)과 View(화면) 사이를 Vue의 반응형 시스템이 연결합니다.
  • Virtual DOM: 이전 가상 트리와 새 가상 트리의 차이를 계산해 실제 DOM 변경을 최소화합니다.
  • SFC: 하나의 .vue 파일에 template·script·style을 모읍니다.
프로젝트 시작 흐름
// src/main.js
import { createApp } from 'vue'
import App from './App.vue'

createApp(App).mount('#app')

// App.vue
<script setup>/* 상태와 로직 */</script>
<template><!-- 화면 --></template>
<style scoped>/* 이 컴포넌트 스타일 */</style>
Q. 개발 중에는 .vue가 보이는데 브라우저가 .vue를 직접 실행하나요?
A. 아닙니다. Vite의 Vue 플러그인이 개발 중 변환하고, 배포 시에는 HTML·CSS·JavaScript로 빌드합니다.

6.이벤트·폼·스타일

v-on · Event modifiers · v-model · scoped style

사용자 입력 흐름
<script setup>
import { ref } from 'vue'
const city = ref('광주')
const submit = () => console.log(city.value)
</script>

<template>
  <form @submit.prevent="submit">
    <input v-model.trim="city" @keyup.enter="submit">
    <button>검색</button>
  </form>
</template>
  • @click은 v-on:click의 축약입니다.
  • .prevent는 기본 동작을 막고, .stop은 이벤트 전파를 막습니다.
  • v-model은 입력값과 상태를 양방향으로 동기화합니다.
  • .trim, .number, .lazy로 입력 동작을 보정할 수 있습니다.
  • <style scoped>는 스타일 적용 범위를 현재 컴포넌트 중심으로 제한합니다.
Q. v-model이 Props를 자식에서 직접 바꾸는 기능인가요?
A. 기본 입력 요소에서는 양방향 바인딩이지만, 컴포넌트에서는 prop과 update:modelValue 이벤트의 약속으로 구현됩니다. 단방향 데이터 흐름 원칙은 유지됩니다.

7.ref와 reactive

반응형 상태 · .value · 재할당 · 반응성 단절

🎙 교수님 강조ref는 모든 타입을 감쌀 수 있고, script에서는 .value, template에서는 자동 언래핑되어 값만 씁니다. reactive는 객체형 전용이며 통째 재할당과 구조분해를 특히 조심해야 합니다.
구분refreactive
대상원시값·객체 모두객체·배열·Map·Set
script 접근count.valuestate.count
template 접근{{ count }}{{ state.count }}
통째 교체user.value = 새객체 가능변수 재할당 시 연결 단절
안전한 기본 선택
import { ref, reactive, toRefs } from 'vue'

const count = ref(0)
const user = ref({ name: '서연' })
count.value++
user.value = { name: '새 이름' }

const state = reactive({ city: '광주', temp: 27 })
state.temp = 28
const { city, temp } = toRefs(state) // 구조분해가 필요하면 반응성 보존
팀 규칙이 없다면 객체까지 ref로 통일하는 방식은 재할당에 안전하고 일관적입니다. 다만 reactive도 틀린 선택은 아니며, 둘의 접근 규칙을 섞지 않는 것이 중요합니다.

8.computed·watch·watchEffect

파생값과 부수효과를 분리하기

💡
computed는 계산기, watch는 경보기입니다. 화면에 보여줄 파생값은 computed, 값이 바뀐 뒤 API 호출·저장·로그 같은 일을 해야 하면 watch를 고려합니다.
도구언제특징
computed기존 상태로 새 값을 계산의존성이 바뀔 때만 재계산·캐시·기본 읽기 전용
watch특정 상태 변경 후 후속 작업대상을 명시하며 new/old 값을 받을 수 있음
watchEffect콜백 안 의존성을 자동 추적처음에도 즉시 실행, old 값 없음
의도를 코드에 드러낸다
const celsius = ref(20)
const fahrenheit = computed(() => celsius.value * 9 / 5 + 32)

watch(celsius, (newValue, oldValue) => {
  console.log(`${oldValue} → ${newValue}`)
})

watch(() => user.value.age, (newAge, oldAge) => {
  // 객체 전체 deep watch보다 필요한 속성만 감시하면 이전 값도 명확하다.
})
Q. 객체 내부 변경이 watch에서 안 잡혀요.
A. ref 객체 전체의 참조만 보고 있다면 { deep: true }가 필요할 수 있습니다. 하지만 과거 값까지 정확히 필요하면 () => user.value.age처럼 필요한 속성만 getter로 감시하는 편이 명확합니다.

9.컴포넌트 Lifecycle

생성 · 마운트 · 업데이트 · 언마운트

setup 실행
상태·함수 준비
onMounted
DOM·초기 요청
onUpdated
DOM 갱신 후
onUnmounted
타이머·리스너 정리
생성한 자원은 반드시 정리한다
import { onMounted, onUnmounted } from 'vue'

let timerId
onMounted(() => {
  timerId = setInterval(refreshWeather, 30000)
})
onUnmounted(() => {
  clearInterval(timerId)
})
  • <script setup> 본문은 컴포넌트 인스턴스 생성 때 실행됩니다.
  • onMounted는 DOM 접근이나 첫 데이터 요청에 흔히 사용합니다.
  • onUpdated에서 다시 상태를 무조건 바꾸면 업데이트 루프를 만들 수 있습니다.
  • 타이머·전역 이벤트·구독·소켓은 언마운트 때 해제해 메모리 누수를 막습니다.

13.Pinia 상태관리

state · getters · actions · storeToRefs

💡
Pinia Store는 앱 여러 곳이 함께 쓰는 공용 서랍입니다. 관련 상태끼리 store 파일을 나누고, 상태 변경과 서버 통신은 actions에 모으면 흐름을 추적하기 쉽습니다.
stores/configStore.js
export const useConfigStore = defineStore('config', () => {
  const unit = ref('celsius')                 // state
  const unitSymbol = computed(() => unit.value === 'celsius' ? '℃' : '℉') // getter
  const toggleUnit = () => {                 // action
    unit.value = unit.value === 'celsius' ? 'fahrenheit' : 'celsius'
  }
  return { unit, unitSymbol, toggleUnit }
})
컴포넌트에서 구조분해할 때
const configStore = useConfigStore()
const { unit, unitSymbol } = storeToRefs(configStore) // state/getter 반응성 보존
const { toggleUnit } = configStore                    // action은 바로 구조분해 가능
🎙 교수님 강조Store를 무조건 많이 만들기보다 “앱 전체에서 공유해야 하는 의미 있는 상태가 무엇인가?”를 먼저 생각하세요. 로그인, 설정, 장바구니처럼 책임 단위로 나눕니다.
토큰을 localStorage에 저장하는 예제는 흐름을 배우기에는 쉽지만, XSS가 발생하면 JavaScript로 탈취될 수 있습니다. 실제 인증 저장 방식은 백엔드와 함께 설계하고, 필요하면 Secure·HttpOnly·SameSite 쿠키와 CSRF 방어를 검토하세요.

비교

헷갈리는 개념 한 번에 구분하기

이름을 외우기보다 “누가 상태를 소유하고, 어떤 일이 필요한가?”로 선택하세요.

ref vs reactive

통째 교체하거나 일관된 규칙이 필요하면 ref. 객체 속성을 묶어 직접 다루면 reactive. 구조분해할 때는 toRefs가 필요합니다.

computed vs watch

기존 상태로 값을 계산하면 computed. 변경 뒤 API 호출·저장처럼 외부 작업을 하면 watch입니다.

watch vs watchEffect

대상과 이전 값이 중요하면 watch. 콜백에서 읽는 의존성을 자동 추적하고 즉시 실행하려면 watchEffect입니다.

v-if vs v-show

거의 바뀌지 않고 초기 비용을 줄이면 v-if. 자주 열고 닫으면 DOM을 유지하는 v-show가 적합합니다.

Props vs Emits

부모 상태는 Props로 내려 읽고, 자식의 변경 의도는 Emits로 올립니다. 자식이 Prop을 직접 수정하지 않습니다.

route vs router

현재 주소·params·query를 읽으면 route. push·replace로 이동하면 router입니다.

Provide/Inject vs Pinia

가까운 컴포넌트 트리에 의존성을 전달하면 Provide/Inject. 여러 화면이 공유하고 추적해야 하는 앱 상태는 Pinia입니다.

VITE_ 설정 vs 비밀값

VITE_ 값은 브라우저 번들에 공개됩니다. API 주소 같은 설정만 두고 비밀번호·서버 토큰은 백엔드에 둡니다.

실전

날씨 대시보드로 전체 개념 연결하기

기능 하나를 만들 때 Vue의 각 도구가 어디에 들어가는지 순서대로 복기하세요.

Router가 도시 페이지를 연다

/weather/:cityId에서 route.params.cityId를 읽습니다.

Pinia가 공용 설정을 제공한다

섭씨·화씨 단위처럼 여러 화면이 공유하는 상태만 Store에 둡니다.

Axios가 서버 데이터를 가져온다

loading을 켜고 try/catch/finally로 data·error·종료를 분리합니다.

computed가 표시값을 만든다

원본 온도를 바꾸지 않고 선택된 단위에 맞는 표시값을 계산합니다.

부모와 자식이 역할을 나눈다

부모는 날씨 상태를 소유해 Props로 내리고, 카드의 새로고침 요청은 Emits로 받습니다.

언마운트와 배포를 마무리한다

타이머를 정리하고 lint → build → preview로 dist를 검증합니다.
